# P-001 — Bootstrap `aidev`

> Handoff note. Output of a long design conversation, written in the system's own plan format, so it doubles as the first worked example. Do not relitigate §2 or §3.

**Status:** active
**Owner:** human + Claude Code
**Created:** 2026-09-19

---

## 1. What we are building and why

A repo-level context layer that lets an AI coding agent work the way a human developer does: know roughly where things live, jump straight there, and remember why the code is shaped that way.

Problem is not documentation. It is **retrieval cost and lost intent**. An agent opening an unfamiliar repo greps blindly — 30–80k tokens to reach ~70% understanding — and has no access to decisions from previous sessions. So it re-proposes rejected designs, breaks unwritten constraints, and conflicts with features it never read.

**Metric:** **tokens-to-context** — tokens between "here is a task" and "agent has everything needed to write correct code."

- Baseline (grep exploration): 30–80k, ~70% coverage.
- Target (map + cards): 1–2k, ~95% coverage.

If a change does not move that number, it is not in scope.

## 2. Decisions locked

| # | Decision | Reasoning |
|---|---|---|
| D1 | TypeScript only | Strict TS + lint is the enforcement layer; JS removes the strongest feedback loop agents have |
| D2 | Three stacks: `next-ts`, `react-ts-node`, `react-ts-python` | Only axis that varies is where the API boundary sits |
| D3 | UI stack fixed: shadcn + Radix + Tailwind + Magic UI, single root theme config | They compose on one token layer; one theming ruleset covers all four |
| D4 | Vendor-neutral `.ai/` source, adapters generated | `.ai/` compiles to `CLAUDE.md`, `.cursor/rules/`, `AGENTS.md`. Write rules once |
| D5 | Two-tier retrieval | `map.md` (~500 tok, always loaded) + per-module `_ai.md` (on demand) |
| D6 | Module cards colocate with code | Centralized docs rot; a file next to the code gets updated in the same diff |
| D7 | Vertical slices: `src/features/<name>/{api,ui,model,tests,_ai.md}` | One capability = one directory = one card = one place to look |
| D8 | Unit tests colocated, E2E at root `e2e/` | Card's `verified_by` must see its tests. E2E spans modules so has no single home |
| D9 | Plans are files, not chat | `.ai/plans/active/P-###.md` → `done/`. Written before the work; doubles as session record with no end-of-session ritual to skip |
| D10 | Fresh session for `/work`, not `/compact` | `/compact` is agent-specific and can't be self-invoked. Plan file *is* the compaction — ~500 tok distillation of a 40k planning conversation |
| D11 | Cards half generated, half hand-written | See §5. Dissolves staleness at the source instead of detecting it |
| D12 | `analyze` ships before `init` | Cold start is the real problem; retrofit is ~100x the market of greenfield |

## 3. Rejected — do not re-propose

- **Multi-language support (Go, Rust, Java, "any framework").** Depth in one workflow is the moat, not breadth.
- **CLI with layer resolver, deep-merge engine, hash-manifest three-way upgrade.** ~3–4 weeks of machinery to avoid maintaining three repos. Three repos is fine. Revisit at eight.
- **`/compact` in the loop.** See D10.
- **Module fingerprint (sha of file list + exports) as staleness gate.** False-positive machine; ignored within a week. Superseded by D11.
- **`/audit`, skills checkbox UI, `init` scaffolding.** v2. Do not move tokens-to-context.
- **Dogfooding on the new portfolio site.** ~4 modules, zero cross-module conflict; validates nothing. Validate on a repo with 15+ modules (§8).
- **Relying on `caveman` (or any terseness skill) to cut context cost.** It cuts *output* tokens; the cost attacked here is *input*.

## 4. Target structure

```
.ai/
├── map.md                        # capability → module → touches. ~500 tok. ALWAYS loaded
├── rules/
│   ├── core.md
│   ├── security.md
│   ├── theming.md                # shadcn/Radix/Tailwind/Magic UI + root token config
│   └── stack.md                  # one of three variants
├── modules/_TEMPLATE.md
├── plans/
│   ├── active/P-###-slug.md
│   └── done/
└── decisions/ADR-###-slug.md

src/features/<module>/
├── api/  ui/  model/
├── tests/                        # unit — colocated (D8)
└── _ai.md                        # the module card

e2e/                              # cross-module specs only
CLAUDE.md                         # thin router. ≤60 lines
```

**Hard budget:** `CLAUDE.md` + `map.md` ≤ 2,000 tokens combined. Build-breaking, not a guideline.

## 5. The module card

Two zones; the split is what makes it survive.

```markdown
---
module: auth
# ── GENERATED — do not hand-edit, regenerated by `analyze` ──
depends_on: [db, email]
consumed_by: [billing, admin]
surface: [getSession, requireAuth, SessionPayload]
key_files:
  - model/session.ts
  - api/login.ts
  - ui/LoginForm.tsx
verified_by: [tests/session.test.ts, e2e/login.spec.ts]
---

<!-- ── HAND-WRITTEN — no tool can infer these ── -->

## Purpose
Session issuance and verification. Owns nothing about permissions.

## Invariants
- **INV-3** `SessionPayload` stays under 4KB — it is stored in a cookie.
  Breaking this silently breaks admin impersonation. (ADR-007)
- **INV-4** `requireAuth` never queries the DB. Billing calls it per-request.

## Gotchas
- Refresh-token rotation is deliberately absent. See ADR-011.
```

**Why the split (D11):** frontmatter is derivable from import graph, export table, file tree — generate it and it can't go stale. Only Purpose, Invariants, Gotchas are hand-written; they change rarely because they describe intent, not structure.

**Invariants are the highest-value data in the system.** "We chose JWT" is inert. An invariant with a stated blast radius is actionable: with auth's card loaded, INV-3 plus `consumed_by: [billing, admin]` lets the agent push back on "store full permission set in the session" before writing code.

**Rule: every ADR that constrains future code must emit an INV line into each affected module's card.** An ADR with no INV is narrative only.

## 6. The loop

```
new session
  └─ CLAUDE.md + map.md load automatically  (~500 tok)

/plan "<requirement>"
  ├─ read map.md → identify candidate modules
  ├─ load ONLY those cards
  ├─ check invariants + consumed_by for conflicts
  ├─ ask clarifying questions — UI/UX, theming, scope
  ├─ WRITE NO CODE
  └─ emit .ai/plans/active/P-###.md

── END SESSION ──

/work P-###           ← fresh session, full context budget
  ├─ load plan + the cards it names. Nothing else.
  ├─ implement, write colocated unit tests
  └─ tick the plan's checklist as it goes

/sync
  ├─ regenerate all card frontmatter from the import graph
  ├─ prompt for new Invariants / Gotchas discovered during the work
  ├─ update map.md
  └─ move plan → .ai/plans/done/
```

**Map fallback rule — appears verbatim in `CLAUDE.md`:**

> If `map.md` does not resolve the task to a module, or the code is not where a card says it is: fall back to grep, complete the task, and then flag the map as stale in your response. Never conclude something doesn't exist because the map omitted it.

Without it the agent looks in one place, finds nothing, proceeds on a confident false negative — worse than no map.

## 7. Build order

Each independently useful; stop and evaluate after T3.

### T1 — `.ai/` skeleton + `CLAUDE.md`
By hand. `CLAUDE.md` ≤60 lines. Plus `_TEMPLATE.md` and plan template.
**Done when:** token budget in §4 verified with a real tokenizer.

### T2 — `analyze` *(keystone — build properly)*
Point at an existing repo; produces `map.md` and a draft card per module.
1. Detect module boundaries: `src/features/*`, `apps/*`, `packages/*`; else cluster by import density.
2. Parse import graph → `depends_on`; invert → `consumed_by`.
3. Parse exports → `surface`. File tree → `key_files`. Test globs → `verified_by`.
4. Read each module, draft 1–2 sentence `Purpose`.
5. **Stub `Invariants` and `Gotchas` as explicit `TODO` prompts. Do not invent them.**
6. Emit `map.md` as union, sorted by capability.

*Stretch:* mine git history for Gotcha candidates (files that change together, reverts, clusters of "fix" commits). Surface as questions for the human, never assertions.

**Done when:** on a real repo, it produces cards a human corrects rather than rewrites.

### T3 — `plan` and `work` commands
`plan` writes files, never code. `work` loads plan + named cards, refuses scope expansion.
**Done when:** one real feature goes plan → new session → work → merged.

### T4 — `sync`
Regenerate frontmatter, prompt for new invariants, update map, archive plan.

### T5 — stack rule variants
Only `rules/stack.md`, `rules/testing.md`, `rules/contract.md` differ per stack (contract absent for `next-ts`; zod shared package for node; OpenAPI codegen + `git diff --exit-code` drift gate for python). Rest byte-identical.

**Not in v1:** `init`, CLI, layer resolution, upgrade path, `/audit`, skills selection.

## 8. Validation

Run after T2.
1. Pick an existing repo with **15+ modules**.
2. Run `analyze`. Hand-correct the five most important cards.
3. Task touching 2–3 modules with a non-obvious conflict.
4. **Run A:** fresh agent, no `.ai/`. Record tokens before first correct edit; whether it found the conflict.
5. **Run B:** same task, same model, `.ai/` loaded. Same measurements.
6. Record both in `.ai/decisions/ADR-001-validation.md`.

**Kill criterion:** Run B not ≥5x cheaper in tokens-to-context, or misses the conflict Run A missed → map layer not earning its cost. Cut back to invariants-only (per-module constraints file, no map, no generated frontmatter) and re-measure. Legitimate outcome, not failure.
